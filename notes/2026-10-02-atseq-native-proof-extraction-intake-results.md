## What the source establishes

- `protocol/index.ts` export-stars native-proof today. A public method or free function there expands supported API unless that one barrel export becomes the explicit same seven runtime/four type names. The chosen internal operation requires that small reviewed barrel edit; it is not an implemented hidden API.
- One existing capability registry can hold the issuer-owned extraction operation. The issuer alone registers it after successful authentication; a second registration owner or caller callback is unnecessary. Returning only CAR bytes preserves the native evidence format and removes a redundant result-row contract.
- Maintained `NodeStore.get` uses its own decoded-node LRU, validates a raw block's CID and deserializes it. P1 already wraps it with strict node/framing/budget checks. `findRpathAndBuildProof` exposes only the final walker-stack node CID set. Exact P1 extraction therefore needs the existing checked walk plus operation-local raw-byte capture; the maintained helper is a test oracle, not a parallel verifier.
- The maintained CAR writer emits its header, then framed entries supplied by the caller. Output ownership, canonical CID ordering, CID deduplication and exact byte preflight remain Atseq's bounded operation responsibilities.
- Current `addExact` parses and validates a whole response before replacing its accumulated Map, but `authenticate` rebuilds a whole CAR and creates another cache. Sharing that existing parser/set check with a commit-plus-new-block serializer avoids the repeated retained-map work. Supplied hashes and constant commit/key/signature checks still repeat in genuine P1 authentication.
- Reusing the same cache makes retained capabilities see admitted bytes without rebinding their identity. Selected commit bytes cannot be reconstructed from metadata when evicted. The future context's bounded selected-commit DATA copy must refill through the genuine fixed-binding issuer, not a skip-verification path.

## Decisions and implementation readiness

Independent review must approve API1–API4 in the contract. In particular, CAR-only output is a proposed refinement of D4's broader bytes/path-result wording. If separate result rows are owed, settle their closed format and charged budget before code. Review must also confirm the exact preserved exports, same-registry ownership, cache-eviction behavior, duplicate physical-block semantics and structural-fault precedence when the collector overflows.

After adoption, P1 extraction owns `src/protocol/native-proof.ts` and its explicit protocol-barrel edit. CAR selection/intake owns `src/protocol/native-observer-car.ts`. These can run in parallel with separate focused fixtures/drivers. Existing `tests/support/native-proof-corpus.ts` supplies genuinely signed P256/secp256k1 trees and hostile interval/missing/cache cases. `tests/support/native-observer-fixture.ts` and `native-observer-portable.ts` supply genuine application/account evidence behind synthetic HTTP, while the real existing `IdentityFetch` still enforces its budgets. Reuse them rather than minting fake capabilities. Actual source/emitted Node 22/24/26 and actual Chromium remain implementation gates.

The future observer route owns context slots/lifetime, all-known-lineage registration, before/root/after I1 observation, registry/current/floor rechecks and PD2 one-use capture. It is not installed here. C1's authority/evaluator extraction and J1's source-only materialization work do not overlap these proposed production files. P4's checked asserted-origin route and P3 durable installed-provenance restore remain separate dependencies.
