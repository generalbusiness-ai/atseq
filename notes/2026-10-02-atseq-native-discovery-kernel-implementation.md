## One existing owner and captured generation

`NativeApplicationOwner` remains private. Its generation remains `{source, domain, authority, outcomeBoundary, prefix}`. A read synchronously owns its selector and payload before asynchronous key validation, captures the actual generation, and uses that generation's genuine source, authority and fixed prefix throughout. Callers cannot supply a snapshot, source, role, authority flag, callback or evaluation constructor. A subject must contain a complete principal/device pair and may narrow selection to one grant ID; public inspection does not prove device possession.

`discover`, `simulate` and `preflight` are module-level facade additions. Supported package and index exports are unchanged. Typed service integration is deliberately a separate full C1 obligation. The existing legacy description envelope is unchanged.

The returned basis owns the app, genesis, definition, interpreted frontier, next frontier position, selected publication, repository method assurance, principal observation, and state/compact-authority commitments. At genesis the publication is null and the external anchor remains explicit. A verified prefix head may exceed the interpreted frontier: a read uses frontier + 1, not publication head + 1. `nativePrefixMethod` reads the selected genuine prefix binding, rather than inferring its method from a historical entry's original root. The genuine unchanged-head prefix fixture tests this accessor; the current coordinator has no separate root-only ingestion operation.

The execution label is `genesis-replay`. This implementation does not install asserted checkpoint generations or upgrade their assurance. P3/P4 restore/import work must carry its reviewed origin distinction through the same owner and must not route an assertion through this replay label. Publication and method evidence also do not establish unique ordering or currentness: the app PDS holding the repository signing key can construct another ordering.

## Selection and shared action stages

Subject preparation scans genuine principals, enabled roles and grants once. It charges rows belonging to other principals too. Temporary references and a subject role set avoid a repeated whole-grant search for each candidate. No durable index, history scan, outcome lookup or second authority tree is introduced.

Each action selects the first eligible admitted grant in the existing bytewise grant-ID order. Different actions may use different grants; they never combine scopes or roles. The shared grant predicate retains ordinary unadmitted, immutable CID, revoked, epoch and signer precedence, followed by scope, action, role and execution checks. An exact missing or unadmitted tombstone filter returns `grant_unadmitted` without inventing an immutable CID. If every admitted candidate fails, the first admitted candidate's reason in that order is stable. A local incomplete search returns unavailable, never a partial denial.

The private action gate and input-schema subroutine are shared. Preflight calls them directly and does not evaluate the fold or construct a successor. Ordered execution and simulation use one full action function and one actual `foldEvaluation`. The public fold API and its error order remain unchanged. Authentication, account/control/activation handling, persistence and poison ownership remain in their existing owners.

Ordered execution retains `#same` after its asynchronous fold. Retained simulation instead checks owner health and whether its captured prefix is contradicted; a concurrent genuine commit may leave an old-labelled simulation valid. A contradiction beyond that old captured head does not rewrite the old result. Persistence uncertainty or contradiction of the captured history withholds it. Five metadata fields come from the actual captured state and selected execution: app, genesis, position, principal and execution. No nonce, actor key, caller role or lease is added.

Successful or authored-ineffective evaluations expose their actual steps and inspected bytes from that one call. Pre-fold denials and thrown evaluations report counters unavailable. Designated framework errors preserve their exact original callsite catches; foreign or unexpected errors become local unavailable only for the read and still escape ordinary ordering. Simulation owns any returned successor and performs no prefix, outcome, persistence or outbox mutation.

## Finite local work without changing shared codecs

Each operation has a private ledger with row and owner-byte limits, defaulting to 100,000 rows and 16 MiB. A caller may only lower positive safe limits. These are conservative owner work bounds, not exact dependency allocation counters or peak-heap limits. Actual candidate visits and scope comparisons are reported separately; normative evaluator counters remain separate from this aggregate budget.

Every growing authority collection is charged when visited: principals, roles, grants, epochs, appointments/powers, grant scopes and assigned roles. Candidate checks consume the same finite row budget. Declared action rows are charged before candidate scanning, so exhaustion cannot hide an unbounded result envelope. Known canonical lengths and existing protocol caps reserve the owner's codec, validator, hash and copy work before those calls; failures retain honest partial counters. No second measurement-only encoding is performed.

Canonical input ownership reserves three times the UTF-16 text length before parse/TextEncoder work, then charges the existing canonical token hooks. The unchanged native key cap is 128 characters; the owner reserves sixteen times its length before maintained validation. Schema calls reserve twice the known canonical upper bound plus the existing input cap to cover bounded repeated passes. Payload identity reserves eight times its known canonical length plus four existing wire-block caps. Opaque crypto, engine and dependency allocations remain unmeasured.

Checkpoint commitments call the existing `checkpointPayloadIdentity` for both state and compact authority. Accounting arithmetic uses the existing 32 KiB chunk bound, known payload length, base64 length, link count and native NSID framing upper bounds; it does not encode alternative framing. Per chunk, the reservation covers JSON spelling/copies, raw payload copies, framing/CBOR/hash inputs and CID formatting. The manifest reserves bounded JSON/CBOR work for every SHA-256 link, framing and decimal length. Codec bytes, parsing, signatures and errors remain unchanged. Boundary tests include empty, 32,767, 32,768, 32,769, 65,536 and 32 MiB payloads using that unchanged codec; the 32 MiB codec check is not a discovery capacity claim.

A private WeakMap holds one successful or pending state/authority commitment pair per exact immutable generation. The first computation pays its traversal and codec bounds. Waiters await the same complete pair; they still pay their own selector, subject preparation, retained checks and result ownership. Failure removes only the exact failed entry, rejects existing waiters and does not retry or reset a ledger. A later explicit operation can try again. New and prefix-only generations are distinct keys. Serialized hashes and snapshots cannot seed this memo; it adds no persisted trust input.
