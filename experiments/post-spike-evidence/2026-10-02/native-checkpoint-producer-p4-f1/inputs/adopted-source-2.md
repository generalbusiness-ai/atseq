# Portable native checkpoints and independent audit

Use the existing native repository to publish a bounded assertion about one captured application generation. Authenticate its publisher independently, preserve its asserted origin, and audit it with fresh genesis replay. Keep one application coordinator, one prefix/index owner, one checked transition implementation and one durable generation cursor. Imported state must never manufacture the existing independently replayed prefix or authority capability.

This P4-D4 proposal joins the accepted [checkpoint bytes](2026-10-01-atseq-checkpoint-policy-bytes.md), [projections](2026-10-01-atseq-checkpoint-projections.md) and [materialized-checkpoint direction](2026-10-01-atseq-materialized-checkpoints.md) with proposed P2 selected-root evidence and P3 materialization handoffs. Those pending designs and the R1/NH implementation reviews are dependencies, not implementation or adoption claims. The [results note](2026-10-02-atseq-checkpoint-joined-results.md) pins actual source and captures. Every proposed runtime vector is **UNEXECUTED**. This child cannot close full P4 or its P3/P2 dependencies.

## Current source and the minimum joined change

`checkpoint-data.ts` and `checkpoint-authority-data.ts` parse DATA: canonical bytes, manifest/chunk identities, exact table/page shapes, compact authority, history-derived identities and complete outcomes. They do not check selected-root checkpoint publication, admit executable source/state, retain accepted authority, produce a checkpoint, restore it, audit it or grant writer readiness. `checkpointPayloadIdentity` computes framing identities; it does not publish or retain records.

R1's `ApplicationGeneration` holds source/domain/authority/outcome boundary/prefix. The existing private authority and prefix constructors accept independently checked history. The genuine prefix owns all positional history, request/nonce/descriptor indexes, original publication provenance and negative floors. Its public `NativePrefix` remains complete-from-genesis only. The present application persistence callback copies a whole projection and dense outcomes; it is not P3's raw-store integration. P1 has no path-proof export operation. P2's proposed capture extension/extraction and P3's proposed installation-owned adapter must be reviewed and implemented before depending on them. In particular, the current observer capture stores encoded blocks plus owner/prior state; it does **not** retain the proposed genuine P1 repository, before/after identity pair and bound reader.

Make the following changes together after review. These names describe private responsibilities, not new profile/package exports:

1. The existing application owner captures one immutable private generation and its genuine prefix owner, known floors, installation execution and P3 storage cursor. An internal `checkpointCapture()` pins that exact generation and exposes no mutable state or caller-created acceptance object. Capture/export are bounded read operations; they cannot accept history or appoint authority.
2. A private publication-admission branch inside that same owner validates a checkpoint and constructs its asserted-origin generation. Retain the distinct `PublishedCheckpointAuthority` view required by the adopted projection decision, issued by this owner as a frozen empty object with a private WeakMap record. It refers to the owner's generation; it is not another authority/state container. No public constructor, callback registration, parsed brand, trust boolean or writer conversion exists.
3. The existing prefix owner stores asserted history coverage separately from independently verified facts in its private record. Its internal origin-sensitive stage/identity lookup operates on the same positional/history index machinery. Do not issue `NativePrefix` or full-prefix verified-history brands for the asserted prior prefix. A caller of existing complete-prefix APIs must still present their genuine complete brand. An unknown historical identity in deferred coverage is unavailable, never proved absent.
4. The existing compact authority transition kernel accepts only the private owner's checked generation input, including origin, and produces an owned successor. Move common checks/folds into one private engine; independent ordered processing, imported asserted suffix execution and fresh audit call that engine through their distinct checked admission branches. Do not expose an unbranded reducer entrance or an alternate grant evaluator. Reuse the reviewed N1/C1/NH gate/input/fold/successor path and preserve its error-stage precedence and counters. Authenticated P2/N1 verification remains mandatory for every new suffix.
5. P3 supplies fixed-generation reads/pins and one real commit cursor to this same coordinator. No checkpoint state database, floor sidecar or audit authority owner is introduced. Pure parsers and byte producers can live in small internal protocol modules; acceptance stays colocated with the existing issuer.

The concrete API and placement above require joint review. Merely widening `openNativePrefix`, feeding imported DATA to `openNativeAuthority`, or accepting a copied `NativeSourceDefinition` would violate the boundary.

## One durable origin, separate execution and identity assurance

Add exactly one closed `origin` union to P3's existing generation metadata, coordinated with its pending source proposal:

```text
{ kind: 'genesis-replay' }
or
{ kind: 'native-publication',
  assertion: assertion byteManifest CID,
  publicationRoot: authenticated publication commit CID,
  head: {position, entry}, frontier: {position, entry},
  priorIndexes: 'complete' | 'deferred' }
```

The native-publication head/frontier are the immutable imported assertion target, not the later live generation's head/frontier. `priorIndexes` records actually established local asserted-row coverage; deferred→complete requires the complete bounded row/index checks. It is not a producer field, independent historical proof, or writer authority. Current generation state/authority/source, tail and outcome coverage remain in their existing fields. Every checked suffix preserves asserted origin. Later producer assertions need not have the same CID as this original import target.

P3 installation execution/restore policy stays separate. Matching actual provenance, directed build equivalence and local trusted transaction checks preserve origin; they cannot upgrade native-publication to genesis-replay. P3's complete-prefix trusted restore branch refuses that origin until P4's private assertion restore branch exists. Once implemented, that branch must revalidate original publication evidence, complete/deferred coverage and origin under the configured supported policy, with fresh current observation before online readiness. The generation may reuse locally checked suffix execution under accepted installed provenance, while its earlier asserted prefix remains asserted.

`genesis-replay` describes independently established derivation; reopening it under accepted local provenance is reused historical execution, not a newly executed audit. Original `plc-audit-v1` / `web-observation-v1` evidence remains per root/principal. No new top-level identity grade duplicates those facts. A matching computational replay does not prove an old web document was current or establish global non-equivocation. Keep target-specific audit progress/evidence in the existing evidence family and commit through the same cursor.

## Bootstrap publication authority outside the checkpoint

Version 1 is `native-publication-v1`. The reader independently configures external app DID/genesis CID, supported format/semantic descriptors, observation policy support, local prior-index mode and finite budgets. Reconstruct genesis under that pin, read its exact appointed observation policy and verify its CID. Derive actual before/after I1 binding from retained method evidence; require the same accepted observation, appointed allowWeb rule and the selected P1 repository key/DID. Authenticate the actual signed repository commit. Handles, revision cursors, notifications, copied binding objects and supplied signing keys cannot replace these checks.

This is the original request's **separately bootstrapped certifier authority** for the adopted initial route: native repository publication authority derives from external configuration plus pinned genesis policy and accepted I1/P1 evidence, not the checkpoint's claimed control powers. It certifies who published an assertion, not that computation occurred. `certify` stays reserved and disabled; designated/quorum certification would require another reviewed assertion version/format, independently appointed control chain, thresholds, revocation and frontier rules. No such infrastructure is added here.

The app PDS holding the repository signing key can construct another ordering. It can also publish false state, grant/authority, source or index assertions. Retained floors detect encountered rollback/conflicts, not unseen alternatives for fresh readers. This accepted authority model is preferable absent evidence requiring another trust mechanism; full audit detects false derivation for its exact target.

The assertion remains the exact adopted closed version-1 object: format/version/app/genesis/head/frontier/definition/state/authority/outcomes/history/sources/evidence/stall/producer. Policies derive from genesis. No origin, mode, assurance, self-CID or publication root is added to its bytes. Publication proof stays outside it to avoid a CID cycle. The selected repository head may be later than its asserted head; prove that exact asserted boundary, then check the later suffix rather than relabeling it as part of the assertion.

## Deterministic production and native transport

Produce from the captured genuine generation only. Export all ordered history through its verified head, current state/compact authority/active definition at interpreted frontier, required historical activation source closures, original exact records, method/proof evidence and installed execution provenance. A source or outcome not retained is not regenerated from a caller projection. A partial local outcome inventory produces null outcomes; a non-null table contains every position 1..frontier with matching history. A stalled next entry retains its diagnostic separately; an unattempted pending tail may have null stall. Frontier zero references genesis.

Reuse the adopted canonical JSON and native framing. Rows use existing closed projection readers and their exact ordering: positional history/outcomes; definition-CID source rows with original file-table order and unused assets; canonical CID evidence rows. Use greedy deterministic page packing: append whole canonical rows while the canonical array remains within 128 KiB/depth 32, then start the next page. If one row cannot fit, reject unsupported checkpoint projection before publication; do not change original records or expand semantic bounds. Empty tables have no pages. Headers preserve page order/counts and exact through target. Check safe arithmetic and configured row limits before enumeration/allocation. Table/state/authority/provenance payloads retain their individual existing bounds.

Split each exact payload into full 32 KiB chunks except the final chunk, encode actual native `content` chunk records, then its ordered byteManifest. Zero-length payloads have zero chunks. Existing manifests admit at most 32 MiB/1,024 chunks; native records retain their 64 KiB cap. Emit owned exact record bytes/CIDs and paths via existing native encoders. Deduplicate byte-identical content by CID for this bounded export, without introducing a second persistent cache/tree. Native CBOR and original signed nonce/signature/request bytes are never rewritten. Freeze literal byte vectors from the actual implementation and compare Node/Chrome; this source packet supplies no invented successful output.

Resolve the original wording “ordinary native records plus content-addressed blobs” explicitly: the adopted first transport represents content-addressed payload bytes in the existing native byteChunk/byteManifest **records**, with their CID-based native content paths. These are not ATproto `uploadBlob` references. Recommend this reviewed native-record route as the initial fulfillment of payload retention/publication, keeping exact content-addressed bytes and ecosystem tools, and ask independent review to ratify that interpretation of full P4. It must not be silently described as literal PDS blob upload. If literal blob transport is required instead, do not close that original obligation: review a minimal ordinary-record blob-reference variant and its getBlob/hash/length/membership rules before implementation. Existing old `SourceStore` verifies raw uploaded blob identity but does not implement that native route. No new blob tree, content union, authority or compatibility layer is assumed.

Publish immutable content in bounded independently reconciled staging batches through the native account writer. Actual serialized bodies must fit its adopted public-write budget; no assumed batch count or oversized fallback. Staging appoints neither active source nor an interpreted position. Obtain the authentic final selected commit, after/before identity evidence and path proofs for the assertion manifest/chunks and every publication-required referenced content record. The assertion's CID is its locator; no mutable latest-checkpoint record is needed. A caller supplies the exact manifest CID or receives it from the producing operation. Content exists before publication is authenticated. A lost reply, account CAS conflict or changed identity requires genuine reconciliation; no successful HTTP reply alone establishes membership. Account/head advancement may leave the captured assertion boundary valid; prove its bridge and report later selected head distinctly. If evidence exceeds a local budget, publication/admission is unavailable rather than falsely complete.

## Admission, readiness and floors

Inside the existing application issuer, capture configuration, source reader, actual P1 root, original I1 evidence, known floors and current owner/cursor before any await. Reconstruct and strictly parse the outer assertion and all mandatory state/active source/compact authority payloads. Run actual `NativeSourceDefinition` admission and state-schema checks under the unchanged native/application/evaluator descriptors; valid executable state cannot be inferred from a hash. Check compact authority's scope/frontier/control/role/epoch/grant/tombstone relationships and loaded original history references without deriving duplicate authority identity arrays. Complete mode validates every history page through asserted head, exact original entry/request bytes/projections, contiguous chain and cross-page uniqueness. These bytes may involve the existing actor signature checks; count that work and do not call it signature-free bootstrap. Historical authority transitions and domain folds still await independent audit.

Prove genesis, selected head, assertion payload membership, asserted boundary and the known-floor bridge under the same genuine root. Follow P2's original-context evidence checks, exact signatures, chain and duplicate machinery for the bridge/suffix. A prior locally verified prefix can coexist with a later asserted remainder in the one owner; import cannot erase its checked facts/floors or downgrade earlier assurance. Import into a live owner cannot lower its interpreted frontier or replace checked components at that same frontier with differing asserted ones. An older checkpoint may be retained as diagnostic evidence, never installed as a newer live generation. Reject lower asserted head, equal-position different CID, scope substitution and incompatible bridge. Higher negative app floors and participant observation floors remain protected even if interpreted state is behind. Account-revision recovery must preserve every registered app lineage, not replace a floor with a new G. New genesis is another explicit pin, never rollback recovery.

Deferred mode loads state/source/authority and requested tail/history pages, validates every actually loaded row, and retains all complete inventory references. Known present identities and new suffix identities are checked. An unknown identity requiring prior absence stalls ordering/interpretation until full prior coverage is loaded and checked; a missing local row is not absent. Deferral can give immediate asserted reads, not unchecked continuous verification. Complete asserted indexes still grant no writer readiness. Writers use the independently checked complete genesis/P3 trusted-local route under NH's current preflight rules.

Any asynchronous completion rechecks the captured owner, relevant floor, source/generation and P3 cursor. Commit origin, current components, selective outcomes, coverage, floors and evidence atomically through one P3 transaction before exposure. A conflict is refused; uncertain commit or late success with stale memory follows P3 poison/checked-restore reconciliation. No in-memory result can erase a durable newer floor. Authenticated required-record absence is invalid checkpoint evidence; archive/cache miss or exhausted local budget is unavailable. Already observed structural/signature/chain/duplicate faults keep precedence. Invalid checkpoint assertions do not retrospectively invalidate otherwise valid ordered history. Foreign runtime faults retain identity, rather than being classified by strings.

## Owned proof inventory and native offline envelope

P2 proposes P1-issued path extraction from the genuine repository. It must retain the selected commit, every visited MST node and each required original record as owned CID-checked bytes; retained cache plus an online lookup is not a portable proof. If a required byte was evicted, export is unavailable. Extraction does not assert untouched-tree canonicality. P4 obtains proofs only through that issuer, never a caller-supplied path result or fake `AuthenticatedRepo`.

Retain assertion-publication proof outside the assertion/evidence payload to avoid recursion. The assertion evidence inventory commits to the original target-history observations, participant repository proof CARs, appBinding/policy records, original source/entry/request bytes and historical roots/method evidence needed for audit. Reuse existing N1 context containers; no second certificate/context union. Identical block bytes can be deduplicated, but distinct root/path/method contexts cannot be relabeled. An evidence row binds bytes, not the truth of its contextual claim. Full independent replay must actually consume those contexts.

Propose a new portable DATA envelope, separate from the older `atseq-archive` spike format. Its canonical CBOR has exactly these fields:

```text
format: 'atseq-native-checkpoint-archive', version: 1,
app: DID, genesis: CID, assertion: byteManifest CID,
publication: {root: commit CID, appIdentity: {before, after}},
blocks: [{cid: canonical DCBOR or supported raw CID, bytes: CBOR byte string}],
licenses: existing closed ArchiveNotice[] sorted by name/version,
replay: fixed installed-runtime instruction string
```

`before/after` use the existing exact `IdentityEvidence` union with raw PLC audit bytes/selected tip or raw web document bytes, encoded as native byte strings, not JSON-normalized method documents. Require closed union fields and original evidence limits; recompute accepted binding through I1. All reference fields are canonical strings; blocks are strictly CID-ordered/unique and bytes hash to their supported codec CID. Duplicate/extra/unknown envelope keys, unsafe counts and noncanonical encoding reject the envelope. Licenses use the existing notice shape, bounded by package size and matched installed notices where required; they never install code. The fixed replay instruction tells the user to use an independently installed supported runtime, external app/G pin and offline import/audit command. An archive never installs runtime, trust configuration, credentials or a writer.

Use the existing 48 MiB archive policy before copying/decoding; preserve P1 per-CAR/block/path and portable proof budgets for reconstructed contexts, plus source/payload/page limits. Do not turn all archive blocks into one oversized CAR: compose bounded original-root proof contexts using the existing writer. Original N1 records identify context; the outer publication names its own commit. Deduplication inside this bounded envelope is transient output storage, not another accepted index. Require complete referenced payload/evidence/source closure for the full offline envelope; if anything required for its advertised genesis audit is absent, export is unavailable and retains a precise missing reference. Online early-use admission can defer loading retained addressable history; it is not a complete offline export. Offline import may read the complete envelope lazily under policy, but it cannot claim current network identity or unseen-history uniqueness.

Import always starts untrusted, checks closed bytes/inventory, then invokes the same publication-admission route with externally configured pin/policy. No separate archive authority importer. Preserve all existing higher local floors. A complete audit runs without credentials, resolver, network clock or live PDS; fresh online readiness later uses I1/P2 current evidence. The browser installed shell must actually remain usable with the app HTTP service stopped, and stale worker/session/cancellation results must not enter another app generation.

## Fixed-target fresh-genesis audit and recovery

Audit captures `(assertion CID, publication root, asserted head, asserted frontier)` and independently checked installed execution, with required retained original evidence. Pin that input inventory. Create a fresh normal genesis execution session through the existing checked source/prefix/authority/application constructors. That is a bounded replay computation using the existing engine, not a second live authority store. Its private results cannot appoint online authority until exact-target comparison and the existing owner/CAS acceptance checks complete.

Verify original ordering/signatures/request/nonce/descriptor uniqueness through asserted head. Authenticate participant observations/grants/control/source activations under their original roots and immutable policy. Fold exactly through asserted frontier, including all ineffective outcomes and unchanged-state transitions. The pending ordered tail still consumes identities but is not folded merely to make the target comparison pass. Never seed this session with checkpoint state, compact authority, claimed indices, outcomes, producer provenance, cached signature-success or asserted-origin capability. Cached exact bytes may be read; acceptance is freshly derived. Resolver, current wall clock and OAuth do not rewrite historical execution.

Derive and compare exact canonical state, active source including ordered/unused files and every required historical activation closure, compact authority, history-derived identity indexes, original projections/evidence coverage, promised complete outcomes including source/reason/message, head/frontier and stall/tail relationship. Producer provenance remains a publisher claim: audit reports actual independently checked execution and any directed equivalence separately; agreement is not proof that the producer ran its claimed binary. A null outcome table makes no historical outcome assertion; audit may generate independent outcomes and retain them as actual new local evidence.

Progress has pending/stalled/matched/mismatched states, immutable target and last independently checked ordering head/interpreted frontier, with an exact missing/limit/fault diagnostic. Persist checkpoints of audit progress through the existing evidence family and same cursor; uncommitted progress is explicitly process-local. Missing bytes/budget/cancellation may stall/resume that same target. A known malformed original signature/chain/duplicate is a fault; do not wait for another missing block to hide it. Result methods return DATA, not a public upgrade token.

On match, the existing coordinator may promote only if its current head/frontier/source/state/authority still equal that target, required complete identity coverage exists, no contradiction/unknown pending publication remains, installation evidence still applies and every known higher floor is preserved. Use the current expected-generation CAS; metadata-only pending/provenance changes do not silently bypass the captured checks. If the live semantic target advanced, retain matched evidence for the old target only; independently replay/verify the additional suffix and compare the complete newer target before upgrading it. There is no automatic extension of audit assurance. Original identity-observation assurance is unchanged.

On mismatch, retain target assertion/publication, compared components, earliest differing position if derivable and independent replay evidence. Stop dependent promotion, assertion-based action dispatch and stronger/trusted state claims. Do not erase higher app/participant floors, silently replace queued execution context, re-sign already recorded work, hide previously returned weaker reads or claim to undo remote actions. Recover with independently replayed state plus freshly verified required bridge/suffix under all known floors; a target behind a higher floor alone cannot replace the live generation. Commit recovery and origin together through P3. If recovery lacks evidence, remain unavailable with preserved evidence/floors. Future independent work unrelated to this assertion is not relabeled compromised by string matching.
